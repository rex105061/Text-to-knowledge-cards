# make-knowledge-cards

把一篇文章变成 5–8 张可复习的知识卡片。每张卡片只讲一个知识点。

这是一个遵循 **Agent Skills** 开放标准的技能（兼容 WorkBuddy、Claude Code、Claude Desktop、Cursor、Codex CLI、GitHub Copilot 等宿主），**不含任何脚本**，纯提示词驱动，整个能力由 `SKILL.md` 里的规则和工作流定义。

当前版本 **v0.1.1**，版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 1. 解决什么问题

读完一篇好文章，过两周通常只剩下"好像挺有道理"这种印象；想留下来，做的笔记往往又退化成抄原文，或者被压缩成丢掉机制和前提的一句话摘要。

这个 Skill 要解决的就是中间的这一步：**把一篇文章压成一组只讲一个知识点、并且每个字段都能回原文核对的卡片。**

由此带来三条明确的设计后果，它们同时也是这个 Skill 与"让模型随便总结一下"的区别：

- **宁可少，不注水。** 原文只够 3 个知识点就输出 3 张，不为了凑 5 张而拆细。
- **不编造。** 卡片里每一句话都要能在原文找到落点，包括理由和因果——哪怕那个理由听起来天经地义。
- **一张卡一件事。** 一张卡片要能单独拿出来复习，不依赖别的卡片。

## 2. 主要功能

### 输入

- 对话里粘贴的文章正文
- 本地 `.md` / `.txt` 文件路径

### 输出

默认 5–8 张知识卡片。每张卡片包含以下四项，`原文依据` 是条件项：

| 字段 | 说明 | 约束 |
|---|---|---|
| 标题 | 点明这一个知识点 | ≤ 15 字（非中文 ≤ 15 词） |
| 核心知识 | 这个知识点本身，脱离原文也能读懂 | 一到两句，只讲一件事 |
| 简明解释 | 为什么成立 / 前提与边界 / 与相邻概念的差别 | 2–4 句，理由必须来自原文 |
| 例子或自测问题 | 二选一 | 原文有例子则复述例子；没有则出一道**能在原文找到答案**的自测题 |
| 原文依据 | 逐字引用原文原话作锚点 | 含具体数字、专有名词（专指机构 / 产品 / 标准 / 人物 / 地点 / 文献名，**技术术语不算**）或结论易被过度推广时必加；中文 ≤ 30 字，非中文 ≤ 30 词 |

### 输出行为

- **默认直接输出到对话**。只有明确要求存文件时才写入 `.md`。
- **语言跟随原文**，除非指定输出语言。英文原文出英文卡片，可另行要求中文版。
- **数量不足 5 张时**输出实际数量，并在卡片区前加一行说明原因。
- **原文是并列清单**（如「N 条建议」）时，会做近义条目去重、按信息增量取舍，并说明合并了几条、保留几张。
- **原文含矛盾或不可确认信息**（多见于口语转写）时，不据此出卡，统一写进卡片区前的「待核」注。
- **同一输入重复运行时，卡片数量可能有 ±1 的波动**（同一篇文章，一次出 5 张、另一次出 6 张）。这是模型解码的固有特性，不是规则失效——实测中同一套规则重复跑同一篇原文，得到过 4 张与 5 张两种结果。要完全可复现，需固定模型版本并降低采样温度。

### 边界处理

| 情况 | 行为 |
|---|---|
| 原文不足 300 字 | 产出能支撑的 1–3 张，说明信息量不足 |
| 原文是口语转写 / 对话记录 | 剔除口水词与重复，只留结论性内容；矛盾的数字、人名、日期进「待核」 |
| 原文只有摘要、目录或标题 | 说明无法提取知识点，请用户提供正文 |
| 文件开头有作者、来源、日期、版权声明等元信息 | 不计入正文，不参与知识点提取；其中的标题可用于生成卡片的文档标题 |
| 原文语言与提问语言不一致 | 卡片沿用原文语言，除非用户指定 |
| 用户指定张数 | 优先满足；原文支撑不到时说明实际可提取数量并全部输出 |
| 用户指定输出格式（JSON、表格等） | 按用户格式输出，但四项字段保持不变 |
| 原文明显自相矛盾 | 指出矛盾处，不据此出卡 |

### 不做什么

- 网页抓取、URL 正文抽取
- PDF、图片、扫描件（请先转成纯文本）
- Anki 导出（`.apkg`、导入包）
- 图形界面、可视化 HTML 卡片

### 硬性约束

`SKILL.md` 里定义了 6 条违反即返工的约束：

1. **不编造**——不补数据、来源、因果、机制、动机、方法论理由、类比。原文写「可能」，卡片就保留「可能」。
2. **一卡一点**——一张卡片出现「A 和 B」两个主张，就拆开。
3. **去重**——同一知识点只留一张卡；分类框架不拆成「有哪几类」加「每类是什么」；「问题→解法」这类因果链的连续两段合并为一张。拆卡的唯一判据：两张卡能各自独立回答一个不同的问题。
4. **不注水**——5–8 是上限区间，不是配额。
5. **不溢出**——不输出原文之外的延伸内容、评论、外部知识。
6. **可答性**——每道自测问题都必须能由原文回答。

## 3. 安装方法

本技能遵循 **Agent Skills** 开放标准（`SKILL.md` + YAML frontmatter）。安装只有一个动作：**把 `skills/make-knowledge-cards/` 整个目录复制到宿主的 skills 目录下。** 无需安装依赖、无需执行任何脚本、无需联网。

### 各宿主的安装位置

| 宿主 | 用户级（本机所有项目） | 项目级（随仓库共享） |
|---|---|---|
| WorkBuddy | `~/.workbuddy/skills/` | `<项目>/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` | `<项目>/.claude/skills/` |
| Cursor 2.4+ | `~/.cursor/skills/` | — |
| Codex CLI | `~/.codex/skills/` | — |
| GitHub Copilot | — | `<项目>/.github/skills/` |
| Google Antigravity | — | `<项目>/.agents/skills/` |

其余兼容宿主（均在用户主目录下）：Windsurf `.windsurf/skills/`、OpenCode `.opencode/skills/`、Cline `.cline/skills/`、Roo Code `.roo/skills/`、Goose `.goose/skills/`、Kiro `.kiro/skills/`、Continue `.continue/skills/`、Trae `.trae/skills/`。

**Claude Desktop 与 claude.ai** 不使用文件夹安装：把 `make-knowledge-cards/` 目录打成 `.zip`，在 Settings 的 Skills 里上传。

```bash
# WorkBuddy（用户级）
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/

# Claude Code（用户级）
cp -r skills/make-knowledge-cards ~/.claude/skills/

# 项目级（以 WorkBuddy 为例，随仓库共享）
cp -r skills/make-knowledge-cards <你的项目>/.workbuddy/skills/
```

Windows PowerShell：

```powershell
Copy-Item -Recurse skills\make-knowledge-cards "$env:USERPROFILE\.workbuddy\skills\"
```

### 两个注意点

- **格式可移植，安装不可移植。** 每个宿主有各自的 skills 目录与注册表，装在一处不会自动出现在另一处。要在多个宿主使用，每个都要装一次。
- **不支持 Agent Skills 的宿主**（如 ChatGPT）无法原生加载。可以退而把 `SKILL.md` 的内容作为提示词粘贴使用，但不会被自动触发。

装好后应存在这个结构。缺 `agents/openai.yaml` 只影响 WorkBuddy 的入口显示，不影响功能——该文件是 WorkBuddy 的入口元数据，其它宿主会忽略它：

```
<skills 目录>/make-knowledge-cards/
├── SKILL.md
└── agents/
    └── openai.yaml
```

## 4. 使用方法

任选一种触发：

```
把下面这篇文章做成知识卡片：

<粘贴正文>
```

```
把 notes/attention-is-all-you-need.md 提炼成知识卡片
```

```
使用 $make-knowledge-cards，把这篇文章整理成 8 张卡片
```

也可以在对话里直接说「知识卡片」「学习卡片」「记忆卡片」「把这篇文章做成卡片」「提取重点知识」。

常见追加要求（都能识别）：

- 指定张数：「做成 6 张」「最多 5 张」
- 指定语言：「给中文版」「用英文输出」
- 指定落盘：「存到 notes/cards.md」
- 指定格式：「输出成 JSON」

## 5. 输入输出示例

### 示例：信息不足的短文（`tests/samples/04-short.txt`）

**输入**

```text
为什么面包放久了会变硬

面包变硬并不是因为水分蒸发，至少不完全是。真正的元凶是淀粉的回生——也就是糊化的淀粉分子在冷却过程中重新排列成有序的结晶结构。这个过程在室温下就会发生，冷藏反而会加速它：4℃ 恰好是淀粉回生最快的温度区间。

所以面包不适合放冰箱冷藏。要延缓变硬，应该冷冻保存，因为 -18℃ 下分子运动被大幅抑制，回生几乎停止。
```

**输出**

```markdown
# 《为什么面包放久了会变硬》知识卡片

> 共 3 张 ｜ 覆盖原文主要知识点
>
> 注：原文可提取的独立知识点为 3 个，未凑数。

---

## 卡片 1：面包变硬的主因是淀粉回生

**核心知识**：面包变硬的主要原因不是水分蒸发，而是淀粉回生。

**简明解释**：原文的表述是"并不因为水分蒸发，至少不完全是"，真正的元凶是淀粉回生——糊化的
淀粉分子在冷却过程中重新排列成有序的结晶结构。这个过程在室温下就会发生。

**问**：按原文，面包变硬的主要原因是什么？

**原文依据**：「真正的元凶是淀粉的回生」

---

## 卡片 2：冷藏反而会加速面包变硬

**核心知识**：面包不适宜冷藏保存。

**简明解释**：原因在于 4℃ 恰好是淀粉回生最快的温度区间。冷藏不但不能抑制回生，反而把它加速了。

**问**：为什么把面包放进冰箱冷藏室是错的选择？

**原文依据**：「4℃ 恰好是淀粉回生最快的温度区间」

---

## 卡片 3：延缓变硬应改用冷冻保存

**核心知识**：要延缓面包变硬，应该冷冻保存而不是冷藏。

**简明解释**：在 -18℃ 下，分子运动被大幅抑制，淀粉回生几乎停止。

**问**：冷冻为什么能延缓面包变硬？

**原文依据**：「-18℃ 下分子运动被大幅抑制，回生几乎停止」
```

这个例子里有两处是刻意的：原文只够 3 个知识点，就直接输出 3 张并说明，没有拆细凑到 5 张；每张卡片的「简明解释」都只用原文给出的理由，没有额外补充机制。

### 其它输入的输出差异

| 输入特征 | 输出上的可见差异 |
|---|---|
| 并列清单（`03`，原文 12 条） | 卡片区前注明「原文共 12 条，第 1 与第 8 条、第 3 与第 4 条属同一知识点已合并，保留 8 张」 |
| 口语转写含矛盾数据（`05`） | 卡片区前出现 `待核：` 注，矛盾的增长率数字不落卡 |
| 英文节选（`06`） | 默认整组英文输出；只够 4 个知识点就出 4 张并注明未凑数；要求中文版时另出 `.zh.md`，`原文依据` 仍保留英文逐字原话 |

## 测试用例

`tests/samples/` 是六类输入，`tests/actual/` 是相应的实际输出：

| 输入 | 类型 | 考察点 |
|---|---|---|
| `01-expository.md` | 概念说明文（认知负荷理论） | 提取机制与效应，处理原文的重复表述 |
| `02-argumentative.md` | 观点论证文（远程办公） | 保留原文的「据称 / 尚未证实」等不确定性 |
| `03-checklist.md` | 并列清单文（12 条建议） | 条目近义去重，清单型文章的取舍 |
| `04-short.txt` | 短文（信息不足） | 只出 3 张，不凑数 |
| `05-transcript.txt` | 口语转写稿（含矛盾数据） | 矛盾数字进「待核」，不据此出卡 |
| `06-english-essay.md` | 英文短节选（兴趣与赚钱，5 段） | 英文输入沿用原文语言；节选只够 4 个知识点，验证英文语境下的不凑数 |

> **第三方材料说明**：`tests/samples/` 中仅 `06-english-essay.md` 来自第三方，为 Paul Graham《When To Do What You Love》（paulgraham.com/when.html，2024 年 9 月）的**节选**（原文第 2–6 段），文件内已注明作者、来源与版权归属。此处仅作技能测试样本使用，**版权归原作者所有**，不在本仓库的 MIT 许可范围内。其余 5 个样本（`01`–`05`）均为本仓库原创文本。
