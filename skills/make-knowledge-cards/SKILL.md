# 制作知识卡片（Make Knowledge Cards）

## 概述

把用户粘贴的文章正文，或用户指定的本地 `.md` / `.txt` 文件，转换为一组知识卡片，默认 5–8 张。每张卡片只承载一个知识点，固定包含四项：标题、核心知识、简明解释、例子或自测问题。

核心纪律只有一句：**卡片里出现的每一样东西，都必须在原文里有落点。**

## 适用与不适用

**适用**

- 用户粘贴文章正文，要求做成知识卡片 / 学习卡片 / 记忆卡片
- 用户给出本地 `.md`、`.txt` 文件路径，要求提炼成卡片
- 用户要求从一篇文章里「提取重点知识」「整理成可复习的卡片」

**不适用**（直接说明不支持，不要尝试变通绕过）

- 网页抓取 / URL 正文抽取 → 告知用户先把正文粘贴进来
- PDF、图片、扫描件 → 告知用户先转成纯文本（Markdown / TXT）
- Anki 导出（`.apkg`、Anki 导入包）→ 只产出卡片文本，不做 Anki 集成
- 图形界面 / 可视化 HTML 卡片 → 只输出 Markdown 文本卡片

## 工作流程

按顺序执行，不要跳步。

### 第 1 步：获取原文

- 用户粘贴正文 → 直接使用。
- 用户给出文件路径 → 用 Read 工具读取 `.md` / `.txt`。
- 文件不是这两类格式 → 回到「不适用」条目说明，并给出替代方案。
- 原文为空、只有标题或只有目录 → 说明无法提取知识点，请用户补充正文。
- 文件开头的标题、作者、来源链接、日期、版权声明等**元信息不算正文**，不参与知识点提取；其中的标题可用于生成卡片的文档标题。同理，正文中的脚注标记（如 `[1]`）若无对应脚注内容，可忽略。

### 第 2 步：通读并标注候选知识点

通读全文一遍，逐条标出候选知识点，同时记住每条在原文中的位置。判断依据见「提取标准」。

同时挑出**矛盾或不可确认的信息**（常见于口语转写：数字前后不一、人名或日期彼此冲突）。这类信息一律不据此出卡；若它对理解全文重要，写进卡片区之前的「待核」注。

### 第 3 步：合并去重

对候选清单两两比较，把属于同一知识点的条目合并为一条。合并时保留更一般、更上游的那条作为卡片主张，把具体细节下沉进「简明解释」。判定规则见「硬性约束」第 3 条。

### 第 4 步：定卡片数量与粒度

- 去重后候选数 ≥ 5 → 按重要性排序，取前 5–8 张。
- 去重后候选数 < 5 → **输出实际数量**，并在卡片区之前加一行说明，不得凑数。
- 一张卡片 = 一个可独立复用的知识点。若某张卡片的「核心知识」由「和」「并且」「；」连接了两个独立主张，拆成两张，或删掉次要的那个。

### 第 5 步：逐卡撰写

按「卡片结构」逐张写。写每张卡片时只对照原文，不引入外部知识。

### 第 6 步：自检后输出

逐条过「自检清单」，任何一条不通过都回到对应步骤修改，然后才输出。

## 卡片结构

每张卡片包含以下四项，多一项少一项都算不合格。「原文依据」是条件项。

**1. 标题**
名词短语或短句，理想长度 ≤ 15 字（非中文 ≤ 15 词）。直接点明这一个知识点，不写「关于……」「浅谈……」这类空壳标题。写完回读一遍，确认没有病句、错字或语义重复。

**2. 核心知识**
一到两句，说清这个知识点本身。必须是可以独立成立的陈述句，脱离原文也能读懂。只讲一件事。

**3. 简明解释**
2–4 句。允许写的内容只有三类：

- 原文已写明的理由、机制、前提、后果
- 原文给出的事实细节（数字、范围、条件）
- 对原文句子的压缩改写

**禁止**自行补充因果、机制、动机或方法论理由。即使这个理由听起来很对、在现实中确实成立，只要原文没写，就不写。这是本技能最高频的失败点，详见「常见失败模式」。

> 反例（禁止）：原文只写「写完隔一天再读一遍，你会发现自己漏掉了大量前提」，卡片却写「因为作者读自己的稿子时会自动补全缺失的上下文」——机制听起来合理，但原文没有。
>
> 正例：「原文只给出了这个观察结果，未展开原因。」

**兜底**：若原文对该知识点只有一句结论、既无理由也无细节，就把「简明解释」改为说明它在原文中的位置、适用范围或前置条件；三者都没有时，直接写「原文未展开」。不要为了填满这一栏而编造。

**4. 例子或自测问题**
二选一，不需要都有。

- 原文有恰当例子 → 复述该例子（可压缩，不可改变含义），前缀标为「**例**」。
- 原文无例子 → 出一道自测问题，前缀标为「**问**」。
- 出「问」之前必须先在原文里找到答句。**永远不要出一道原文答不出的题。** 优先问「是什么 / 为什么 / 在什么条件下 / 有什么后果」，避免需要外部知识才能回答的评价类问题。找不到答句就换个问法；换不出来就改用「例」，或说明该知识点不适合出题。

**5. 原文依据（条件项）**
当卡片含具体数字、专有名词，或该结论容易被过度推广时，追加一行：逐字引用原文中的一小段原话作为锚点（中文 ≤ 30 字；非中文 ≤ 30 词）。纯概念性、无过度推广风险的卡片可省略此项。引用必须逐字，不得改写。

## 提取标准

**算重要知识（优先做卡）**

- 定义与概念边界：某术语指什么、不指什么
- 机制与因果：为什么发生、通过什么路径发生
- 判别与对比：A 与 B 的区别、什么情况下选哪个
- 规则与启发式：可迁移到新情境的操作准则
- 带条件的量化事实：数字及其成立前提、统计口径、时间范围
- 框架与步骤：解决一类问题的结构化流程

**丢弃**

- 铺垫、过渡句、口号式总结、情绪化修辞
- 无迁移价值的个人轶事、闲聊、广告与推广
- 对同一观点的重复陈述，以及举例之后的再次复述
- 原文只提一句就带过、未加展开的名词（除非它正是全文核心）
- 纯时效性安排（某次会议时间、活动日程），除非它本身就是知识点

**重要性排序依据**：承载全文主张与结论的 > 被其他知识点依赖的 > 可独立迁移应用的 > 细节补充。

**并列清单型文章的补充规则**：原文若是无轻重之分的条目清单（如「N 条建议」），上面的排序失效，改用以下顺序取舍——可迁移范围更广的优先、反直觉且信息增量更大的优先、原文给出了理由或例子的优先；最常规、最容易自己想到且原文未加论证的条目优先剔除。筛选后若超出 8 张，在卡片区前说明「原文共 N 条，已合并 M 条重复项，保留 K 张」。

## 硬性约束（违反即返工）

1. **不编造**：卡片中每一项都必须能在原文找到落点。不补数据、不补来源、不补因果、不补机制、不补动机、不补方法论理由、不补原文没有的类比。原文写「可能」「据称」「一般认为」，卡片保留同等不确定性，不得升级为断言。
2. **一卡一点**：一张卡片只讲一个知识点。若一张卡片能拆成两张且两张都成立，就拆开。
3. **去重**：同一知识点只保留一张卡片。判定重复 = 两者可互相推导，或其中一条是另一条的特例、子集、换一种说法。合并时取更一般的那条。**分类框架类**知识点：框架本身算一个知识点，不得拆成「有哪几类」加「每类是什么」；该框架「该怎么用」的直接推论写进「简明解释」，只有当这个推论可以脱离框架独立指导行动时才拆成独立卡片。
4. **不注水**：低于 5 张就是低于 5 张。禁止为了凑数拆细粒度、复制粘贴、把废话包装成卡片。
5. **不溢出**：不输出原文之外的延伸阅读、个人评论、外部案例、领域补充知识。
6. **可答性**：每道自测问题都必须能由原文回答。

## 输出格式

默认在对话中直接输出 Markdown 卡片。用户明确要求存文件时，再写入 `.md`。

```markdown
# 《原文标题或首句概括》知识卡片

> 共 N 张 ｜ 覆盖原文主要知识点

---

## 卡片 1：标题

**核心知识**：一到两句。

**简明解释**：2–4 句。

**例**：原文中的例子。    ← 或 **问**：自测问题

**原文依据**：「逐字引用，不超过 30 字」    ← 条件项

---

## 卡片 2：标题
...
```

- 卡片之间用 `---` 分隔，编号从 1 连续到 N。
- 引言引用块里只写「共 N 张 ｜ 覆盖原文主要知识点」，不写评论。
- 需要加注时，按以下顺序追加在引用块下方（有几条写几条，没有就不写）：
  1. `注：原文可提取的独立知识点为 N 个，未凑数。`（仅当少于 5 张时）
  2. `注：原文共 N 条，已合并 M 条重复项，保留 K 张。`（仅当原文为并列清单且做了合并筛选时）
  3. `待核：<矛盾点说明>。`（仅当存在矛盾或不可确认信息时）
- 结尾不加总结段、不加推荐语、不加「希望对你有帮助」这类收尾。

## 常见失败模式（实测高频，写完必查）

| 失败模式 | 表现 | 修法 |
|---|---|---|
| 补理由 | 「简明解释」写了原文没有的因果或机制，例如给一条只有结论的建议硬凑「因为……」 | 回原文找那句话；找不到就删掉，改写为「原文未展开」 |
| 补方法论 | 给一项研究补上「随机分组消除了自选择偏差」这类原文没有的统计理由 | 同上。这是最隐蔽的一类编造，因为术语听起来专业 |
| 出不可答的题 | 自测问题问「为什么必须这样做」，而原文只写了「要这样做」 | 先在原文找答句，找不到就换成「是什么 / 在什么条件下」类问题 |
| 卡内塞两点 | 一张卡的核心知识是「A 和 B」 | 拆成两张，或删掉次要的那个 |
| 近义条目重复出卡 | 清单型原文里「先写结论」和「先给读者答案」各出一张 | 按去重规则合并，并在卡片区前写明合并了几条 |
| 凑数 | 原文只有 3 个知识点，硬拆成 5 张 | 直接输出 3 张，加数量说明 |
| 跨情境外推 | 把限定在特定行业或特定样本的研究结论写成普适规律 | 把原文的适用边界一起写进「简明解释」 |

## 自检清单（输出前逐条确认）

1. 卡片数在 5–8 之间，或已说明为何不足、已说明筛选依据？
2. 每张卡片只有一个知识点？「核心知识」里没有被「和 / 并且 / ；」串起的两个主张？
3. 四项是否齐全，`例` / `问` 标签是否正确，标题是否 ≤ 15 字且只指向一个知识点？
4. 「简明解释」里的每一句都能指回原文的具体内容？（重点查「因为……」「之所以……」「这样做的目的是……」这类句子在原文是否真有）
5. 有没有原文中查不到的数字、人名、因果、机制、类比？（有 → 删）
6. 原文带不确定性的表述，卡片是否保留了同等不确定性？
7. 每道「问」都能在原文找到答句？（找不到 → 换题）
8. 是否存在两张卡片讲同一件事？（有 → 合并）
9. 是否混入了原文之外的延伸内容、评论、外部知识？（有 → 删）
10. 任意剔除一张后，是否只是变短而不损失信息？（是 → 那张大概率是凑数的，删掉）

## 边界与失败处理

| 情况 | 处理方式 |
|---|---|
| 原文不足 300 字 | 说明信息量不足以支撑多张卡片，产出能支撑的 1–3 张，不硬凑 |
| 原文是对话记录或口语转写 | 先剔除口水词与重复，只保留结论性内容；矛盾的数字、人名、日期写进「待核」注，不据此出卡 |
| 原文只有摘要、目录或标题 | 说明无法提取知识点，请用户提供正文 |
| 原文语言与用户提问语言不一致 | 卡片沿用原文语言，除非用户指定输出语言 |
| 用户指定张数（如「要 10 张」） | 优先满足用户；若原文支撑不到，说明实际可提取数量并输出全部 |
| 用户指定输出格式（如 JSON、表格） | 按用户格式输出，但每张卡片的四项字段保持不变 |
| 原文明显自相矛盾 | 指出矛盾处，说明不据此出卡，请用户确认后再提炼 |
